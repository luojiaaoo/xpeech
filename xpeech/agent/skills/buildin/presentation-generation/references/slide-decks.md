# HTML 幻灯片架构

本技能只交付浏览器可播放的 HTML 幻灯片，不包含其他文档或图片格式的导出流程。

## 架构选择

### 多文件架构（默认）

适合超过 10 页、课件、研究报告或需要逐页维护的演示。

```text
deck/
├── index.html
├── slides/
│   ├── 01-cover.html
│   ├── 02-agenda.html
│   └── 03-content.html
└── assets/
    ├── images/
    ├── fonts/
    └── shared.css
```

从 `assets/deck_index.html` 复制聚合页为 `index.html`，只修改 manifest、标题和必要的视觉变量。聚合页负责：

- iframe 页面隔离；
- 左右方向键、Home、End 和数字键导航；
- URL hash 跳页；
- 页码显示；
- 16:9 画布缩放与 letterbox；
- `localStorage` 保存播放位置。

每页单独维护 CSS，避免跨页污染。共享图片、字体和基础变量放入 `assets/`，页面只使用相对路径。

### 单文件架构

适合不超过 10 页、需要共享状态或轻量动画的演示。复用 `assets/deck_stage.js`：

```html
<deck-stage width="1920" height="1080">
  <section class="slide active">...</section>
  <section class="slide">...</section>
</deck-stage>
<script src="./assets/deck_stage.js"></script>
```

不要重写播放器的缩放核心。脚本必须放在 `</deck-stage>` 后，active slide 才能显示。

## 页面画布

- 固定设计尺寸：`1920×1080`。
- 内容安全区：左右至少 96px，上下至少 64px。
- 标题建议 48～80px，正文建议不小于 24px。
- 使用 CSS Grid/Flex 组织主要结构，绝对定位仅用于明确的装饰层。
- 不依赖页面滚动展示核心内容；单页必须在一屏内完成表达。

## 叙事节奏

常见页面角色：

1. 封面：建立主题和情绪。
2. 目录：告诉观众接下来的路线。
3. 问题：定义背景、痛点或机会。
4. 洞察：突出一个关键结论。
5. 方案：解释结构、流程或产品。
6. 证据：数据、案例、对比或时间线。
7. 行动：给出下一步和责任人。
8. 结尾：强化一句记忆点。

不要让连续多页使用完全相同的版式。每 2～3 页安排一次视觉节奏变化，但字体、色板、网格和页码位置要保持一致。

## 图表和媒体

- 优先使用真实素材和语义明确的图表。
- 图表必须有标题、单位、来源和突出结论。
- 图片设置合理的 `object-fit`，避免人物或产品主体被裁切。
- 外链资源不稳定，交付前尽量下载到项目的 `assets/`。
- 不用 Emoji 代替正式图标。

## 自适应要求

固定画布应按比例缩放并居中，不得随窗口比例拉伸。至少考虑：

- 16:9 全屏窗口；
- 1440×900 等非 16:9 窗口；
- 浏览器工具栏占用高度后的普通窗口。

缩放只改变整体比例，不重新排版页面内部元素。舞台中心与视口中心应保持一致，超出区域使用 letterbox 留白。

## 交付要求

- 入口固定为 `index.html`。
- 先通过静态检查确认所有引用文件存在。
- 使用 `create_browser_preview` 生成预览 URL。
- 使用 `send_file` 发送自包含 HTML；多文件项目可打包发送。
- 不提供其他文档格式的转换产物或导出命令。
- 用户需要 PPT 文件时，必须打包并发送完整 HTML 项目，再提醒用户通过桌面智能体自行转换。
