# HTML 幻灯片静态验证

验证目标是尽可能在不启动浏览器、CDP、Playwright 或转换工具的前提下发现结构、资源和布局问题。

## 1. 文件检查

- `index.html` 存在且为 UTF-8。
- manifest 中列出的每个页面都存在。
- HTML 中引用的本地 CSS、JavaScript、图片和字体均存在。
- 引用使用相对路径，不包含工作区外路径。
- 不存在 HTML 之外的生成物或相关导出脚本。

可使用 `rg` 检查引用，再使用 `list_dir` 或 Shell 的只读命令核对文件。

## 2. HTML 结构检查

- 每页包含唯一且有意义的 `<title>`。
- 标题层级合理，重要文本不是纯装饰图片。
- `<img>` 包含 `alt`；装饰图片使用空 `alt`。
- 标签闭合、ID 不重复、脚本加载顺序正确。
- 单文件架构中 `deck_stage.js` 位于 `</deck-stage>` 后。

## 3. 画布与布局检查

- 设计画布为 1920×1080 或同等 16:9 比例。
- 页面不依赖纵向滚动才能看到核心内容。
- 正文不小于 24px，关键文字与背景有足够对比度。
- 内容保持在安全区内，绝对定位元素没有明显负坐标或越界尺寸。
- stage 使用等比缩放和居中逻辑，非 16:9 窗口不会拉伸。

## 4. 交互代码检查

- ArrowLeft/ArrowRight 可以前后翻页。
- Home/End 可以跳转首尾页。
- 当前页码会随切页更新。
- URL hash 与当前页面同步。
- 页面索引受到上下界保护。
- 刷新时读取的 `localStorage` 值经过合法范围校验。

## 5. 预览交付

静态检查通过后，调用 `create_browser_preview` 托管最终 HTML。不要自行启动 HTTP 服务。将预览地址交给用户进行最终视觉确认；如用户反馈裁切、字体或资源问题，修改 HTML 后重新生成预览。

如果用户需要 PPT 文件，还必须确认 HTML 项目压缩包包含 `index.html`、全部页面和本地资源，并在最终回复中包含 `SKILL.md` 规定的转换提醒原文。
