# 自我改进

先完成当前任务，再把值得复用的改进整理成备忘录。所有经验文件位于当前用户工作区的 `memory/self-improving/`。

## 何时使用

- 用户明确纠错、要求记住做法或要求复盘时，先处理当前问题；只有能指导未来同类任务的内容才保存。
- 当前任务与已有备忘录的具体内容相关时，读取并应用；只因分类名含“工具”“编码”等宽泛词，不必加载整个分类。
- 实际解决问题后发现可验证、可复用的方法，可以整理；没有新经验则不写文件、不做例行总结。
- 用户查询、整理或遗忘经验时，按其指定范围处理。

一次性的文字修改、日期或数值更正、临时方案，不自动变成长期规则。沉默和一般性表扬不作为偏好依据。

## 怎么读

从已有目录树选择相关分类。该分类有 `必读.md` 时先读，再按任务读取主题文件；同一任务已读取且未变化的内容无需每次工具调用前重读。

先核实适用范围，再使用规则。当前明确要求优先，项目内约定不扩大为全局要求；旧对话只能提供历史背景。找不到文件、准备新建文件或怀疑目录过期时，检查实际目录后再决定。

## 怎么写

1. 先读相关必读和主题文件，判断新内容是补充、纠正、替代还是重复；重复且没有新条件时不写。
2. 优先修订已有分类和文件，把新旧内容总结成当前有效的规则或方法；不按轮次、日期或每次失败追加日志。
3. 纠正可重复的错误做法、以后执行该类任务前必须遵守的要求，写入对应分类的 `必读.md`。知识、步骤、示例和待验证推测写入主题文件，不因“值得记住”就列为必读。
4. 保留必要的适用范围、依据和不确定性。用户明确要求可直接按原范围记录；技术方法按验证结果记录，不把自己的推测写成用户偏好。
5. 保存后核实内容完整。只有已有文件确实无法容纳主题时才新建文件，已有分类均不合适时才新建分类。

普通经验留在分类文件中。仅将非常重要、稳定且已确认、需要长期遵循的规则精简写入 `memory/MEMORY.md`，不重复搬入方法细节或复盘过程。

## 目录约束

- 只用“分类目录 → `.md` 文件”两层；正文用章节组织，不再嵌套目录。
- 最多 12 个分类，每类最多 32 个文件，包含 `必读.md`。
- 目录名、文件名主体（不含 `.md`）最多 20 字，名称直接表达主题。
- 不在数据根目录另放经验文件，不创建索引、清单或日期日志，不使用隐藏目录或符号链接。
- 达到上限时先聚合相关主题，不通过近义分类、深层目录或删掉有效规则来凑数量。

## 按需参考

- 提炼或修订经验：读 [references/learning.md](references/learning.md)，判断必读与知识、证据与推测、适用范围。
- 合并分类或处理容量上限：读 [references/storage.md](references/storage.md)。
- 查询、遗忘或导出：读 [references/operations.md](references/operations.md)。

读取和写入只覆盖本次相关文件。用户授权清晰时直接处理；含义或范围有歧义且会影响结果时才询问。读写失败时说明实际完成情况，不把未保存的内容说成已记住。
