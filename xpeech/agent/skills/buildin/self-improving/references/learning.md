# 提炼与修订经验

先判断新信息是否改变未来同类任务的做法。能提炼出有适用条件的规则或可验证方法时再保存；单次任务参数和偶发事实更正留在当前任务中。

## 必读保存纠错与执行约束

`必读.md` 只保存该类任务执行前必须知道的短规则。用户明确纠正了一个可重复的错误做法，或要求今后在明确范围内遵守某个约定，才适合放入这里。例如：

```markdown
# 工具使用必读

## 修改前读取
- 范围：使用文件编辑工具修改已有文件。
- 要求：先读取当前内容，再做精确替换，保留无关修改。
- 依据：用户明确指出按旧内容覆盖造成了其他修改丢失。
```

规则包含“适用条件、应该怎么做、纠正的错误”。已有同类规则时修订原段落，不为再次犯错新增一份。详细原因、示例和操作步骤放主题文件，必读只保留执行要求和必要的文件引用。

一次性纠正参数或事实，不足以形成必读规则。未证实的错误归因、一般知识、试验性建议也不放入必读。

## 主题文件保存方法与知识

例如 `工具使用/失败处理.md`，按主题整合错误分类、检查步骤和已验证的重试条件。新证据补充已有方法时，直接融入对应章节，合并重复表述。

按需要注明适用环境、项目、版本或前提。只记录验证过的结论；原因未查明时，分别写清实际观察、已奏效的处理和仍待验证的推测，不将一次奏效归因为通用规律。

## 不同依据分别处理

- 用户明确的长期要求：在其指定范围内直接采用，无需重复确认。
- 已验证的技术方法：可以保存，并写明验证条件；不要求用户为每条技术笔记确认。
- 自己提出的改进猜测：若值得继续验证，放在主题文件中注明“待验证”，不作为执行约束或用户偏好。
- 多次独立成功可增强依据，但不能虚构成功次数，也不凭固定次数自动提升为全局规则。

同一项目内的新明确要求可修订旧规则；不同项目或环境下的差异分别保留条件，不互相覆盖。只有冲突仍影响当前执行、且无法由范围或用户最新要求消解时才询问。

## 修订后的结果

每个主题保留一份当前有效的正文。短规则以必读文件为准，详细方法以主题文件为准；引用细节时指向对应文件，避免在多处完整复制同一规则。

经验经过确认或多次使用，仍默认保留在分类文件中。是否需要精简写入 `memory/MEMORY.md`，按技能入口的重要性和长期适用性判断。
